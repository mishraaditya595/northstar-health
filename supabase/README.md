**Status:** Six of seven committed P2-01 migrations are recorded on the **development** Supabase project; the final completed-only migration must be reconciled before P2-05 can be applied there. P2-01 Supabase groundwork, P2-02 authentication, P2-03 outbox and P2-04 authenticated foreground uploader are merged in PRs #13–#16. P2-05 server progress aggregation [PR #17](https://github.com/mishraaditya595/northstar-health/pull/17) **merged on 2026-10-26**, but is not deployed to the hosted project; P2-06 restore feed is merged in PR #18 and reviewed conflict point-lookup is in [draft PR #24](https://github.com/mishraaditya595/northstar-health/pull/24); production rollout still needs live Auth/RLS E2E and physical-device QA. See [ADR-0005](../docs/adr/0005-mandatory-auth-and-workout-sync.md) and [Cloud Sync Contract](../docs/CLOUD_SYNC.md).

Ten ordered migrations (nine merged, one P2-06 draft) under `supabase/migrations/` create and then harden `workout_records`, `workout_sync_operations`, `northstar_private.workout_owner_cursors` and the authenticated `sync_workout` RPC. The initial migration is retained because it was applied to the dev instance. The hardening adds strict required-field checks and typed values, hashed 90-day receipts, per-owner change cursors, and conditional revision updates. The third migration fixes a validator special-form spelling error. The fourth adds owner-triggered expired-receipt pruning and safely revokes public execution of the hosted-only RLS event-trigger function if present; the fifth and sixth close numeric, UUID and tombstone bugs; the seventh restricts sync to completed workouts (ADR-0005), the eighth (P2-05, **not applied to hosted development**) derives original-local completion dates and exposes an owner-scoped read-only progress RPC; the ninth (P2-06 merged) adds a read-only owner-scoped change feed, payload-free tombstones, and a **database restore epoch** that must be echoed by clients on every request after the initial zero-cursor bootstrap. The tenth migration (draft PR #24) adds an authenticated read-only `get_workout_for_resolution` RPC for point-in-time conflict review. A private owner-scoped definer helper reads the current owner counter and global epoch without exposing tables. A privileged invoker-only epoch rotation is **mandatory after any database restore and before resuming app traffic**; see [restore runbook](RESTORE_RUNBOOK.md). The foreground Flutter restore/import pipeline is merged; PR #24 adds explicit conflict review. Hosted rollout remains outstanding.

`supabase/tests/workout_sync.test.sql` is a rolled-back synthetic pgTAP suite (66 assertions) covering account boundaries, JSON validation, replay, deletion and processing. `supabase/tests/workout_progress.test.sql` now includes 65 assertions covering per-day progress, missing-load and missing-counter semantics, INSERT/UPDATE/DELETE permissions, UTC output, extreme dates, correction/tombstones and owner isolation (129 for P2-01/P2-05), while `supabase/tests/workout_restore_feed.test.sql` now adds **76 restore assertions plus 19 point-lookup assertions (226 total expected)**, including rotation after an overtaken cursor (8 vs counter 10) and restricted table/function privileges. A read-only precheck on 26 October 2026 found zero active completed dev records and zero malformed/zone-free timestamps. The P2-05 migration requests `SET LOCAL TIMEZONE = 'UTC'`, but clean CI replay emits PostgreSQL warning `25P01` (SET LOCAL outside a transaction); do **not** assume the intended UTC setting took effect. Review an additive fix / deploy procedure before any data-bearing hosted P2-05 rollout. On populated production databases its backfill UPDATE and ordinary CREATE INDEX can block writes, so profile the table and schedule maintenance or split into batched/backfill and concurrently indexed deployment. Real two-connection concurrency tests and release/privacy gates remain open.

Do not commit private or service-role keys, database credentials, bearer tokens, real workout records, raw platform health data, or full ObjectBox database files. Flutter may use a public project URL and publishable key with authenticated sessions; only the backend controls privileged storage and server computations.

**Rollback:** Do not delete workout tables. Revoke authenticated RPC EXECUTE to halt cloud writes, preserve ObjectBox queues, then deploy a corrective migration. Do not replay an older vulnerable function over newer production migrations.
