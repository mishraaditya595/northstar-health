## Schema and deployment

The 11 immutable, ordered `supabase/migrations/` files consist of: seven P2-01 foundational/hardening migrations; P2-05 day-level progress aggregation; P2-06 restore feed/epoch; P2-06 reviewed point lookup; and P2-07c **`20261027180000_p2_07c_recent_account_session_gate.sql`**. Replay **all eleven**, in filename order, for a clean environment. The Auth deletion Edge Function is separately deployed following [ACCOUNT_DELETION_RUNBOOK.md](ACCOUNT_DELETION_RUNBOOK.md). Do not edit past applied migration files.

The data model uses owner-scoped `public.workout_records` (completed-workout JSON payloads, revisions, tombstones and derived progress), `public.workout_sync_operations` (SHA-256 request hashes and 90-day replay receipts), private per-owner cursors, a strict authenticated `sync_workout` RPC, owner-scoped progress/read APIs, an epoch-aware paginated change feed and an authenticated point lookup. Client table mutation is forbidden. The `authorize_account_deletion()` fresh-session check never gives clients a service-role key; only `functions/delete-account` calls Auth admin hard deletion, with cascade cleanup. See [CLOUD_SYNC.md](../docs/CLOUD_SYNC.md) for the wire contract and [RESTORE_RUNBOOK.md](RESTORE_RUNBOOK.md) for **mandatory epoch rotation after snapshot/PITR restore**.

## Validation and operations

`supabase test db` performs clean local pgTAP suite testing for sync, progress, restore, conflict point lookup and fresh Auth-session authorization. An earlier PR #24 run covered **226/226 assertions across the first four suites**, but that result is historical and **does not prove the eleventh migration, all current tests, hosted signed-JWT RLS, stale-token safety or physical-device behavior**. The GitHub Actions Supabase SQL workflow must pass on the current commit. Follow [P2-08 release validation](../docs/implementation/phase-2/p2-08-workout-export-release-validation.md) and the [account deletion runbook](ACCOUNT_DELETION_RUNBOOK.md) for hosted destructive testing with disposable accounts.

The P2-05 migration's `SET LOCAL TIMEZONE = 'UTC'` emitted PostgreSQL warning `25P01` during an earlier clean CLI replay; do **not** assume effective timezone changes. Confirm UTC behavior in an actual transaction and review an additive remedy if required before a data-bearing backfill. Its backfill and regular index creation can block writes on larger databases. Independently test transaction boundaries, RLS, two-device races, full-purge scheduling for expired receipts on inactive accounts and any rollback on a nonproduction project.

Do not commit private or service-role keys, database credentials, bearer tokens, real workout records, raw platform health data, or full ObjectBox database files. Flutter may use a public project URL and publishable key with authenticated sessions; only the backend controls privileged storage and server computations.

**Rollback:** Do not delete workout tables. Revoke authenticated RPC EXECUTE to halt cloud writes, preserve ObjectBox queues, then deploy a corrective migration. Do not replay an older vulnerable function over newer production migrations.
